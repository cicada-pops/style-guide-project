# Выполнение SQL-запроса

```text
POST /api/cases/{case_id}/execute-sql/
GET  /api/sql-task/{task_id}/
```

Запрос игрока выполняется в два шага.
Сначала фронтенд отправляет SQL-запрос и получает идентификатор задачи.
Затем по этому идентификатору запрашивает результат.

Запрос выполняется в фоне воркером Celery, поэтому результат приходит не сразу.

Базовый адрес API при локальном запуске — `https://sqlhunt.com:8000`.

## Авторизация

Оба метода требуют токен доступа JWT в заголовке `Authorization: Bearer <access-token>`.
Токен выдаёт метод `POST /authentication/api/token/`.

Один пользователь может отправить не больше 100 запросов к API в минуту.

## Шаг 1. Отправка запроса

```text
POST /api/cases/{case_id}/execute-sql/
```

### Параметры пути

| Параметр | Тип | Описание |
| --- | --- | --- |
| `case_id` | integer | Идентификатор дела |

### Тело запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `sql` | string | Да | Текст SQL-запроса |

Сервер принимает не любой запрос:

- разрешён только один запрос `SELECT`;
- обращаться можно только к таблицам из материалов дела;
- нельзя использовать точку с запятой `;`, комментарии `--` и `/* */`, а также `INTO` и `RECURSIVE`;
- если в запросе нет `LIMIT`, сервер добавляет `LIMIT 1000`.

### Пример запроса

```bash
curl -X POST "https://sqlhunt.com:8000/api/cases/1/execute-sql/" \
  -H "Authorization: Bearer <access-token>" \
  -H "Content-Type: application/json" \
  -d '{"sql": "SELECT id, name FROM person LIMIT 5"}'
```

### Ответ

```json
{
  "task_id": "3f1c2a9e-8b7d-4c51-9a0e-6d2f4b8c1e77"
}
```

### Коды ответов

| Код | Когда возвращается | Текст ошибки в поле `error` |
| --- | --- | --- |
| `202` | Задача создана | — |
| `400` | Поле `sql` пустое | `Поле 'sql' не может быть пустым` |
| `400` | Игрок ещё не начал это дело | `Прогресс по делу не найден` |
| `401` | Токен не передан или истёк | Стандартное сообщение Django REST Framework в поле `detail` |
| `403` | У игрока не хватает опыта для этого дела | `Недостаточно опыта для доступа к делу` |
| `404` | Дела с таким `case_id` нет | `Дело не найдено` |
| `500` | Не удалось поставить задачу в очередь | `Ошибка запуска задачи: <текст исключения>` |

## Шаг 2. Получение результата

```text
GET /api/sql-task/{task_id}/
```

### Параметры пути

| Параметр | Тип | Описание |
| --- | --- | --- |
| `task_id` | string | Идентификатор задачи из ответа на шаге 1 |

### Пример запроса

```bash
curl "https://sqlhunt.com:8000/api/sql-task/3f1c2a9e-8b7d-4c51-9a0e-6d2f4b8c1e77/" \
  -H "Authorization: Bearer <access-token>"
```

### Ответ

Метод всегда возвращает код `200`.
Состояние задачи передаётся в поле `status`.

| `status` | Что значит | Другие поля ответа |
| --- | --- | --- |
| `PENDING` | Задача ещё выполняется | — |
| `SUCCESS` | Задача завершена | `result` |
| `FAILURE` | Воркер не смог выполнить задачу | `error` |

Пока `status` равен `PENDING`, повторяйте запрос.

Задача завершена:

```json
{
  "status": "SUCCESS",
  "result": {
    "columns": ["id", "name"],
    "rows": [[337, "Громов Илья Петрович"], [512, "Лаптева Анна Сергеевна"]]
  }
}
```

!!! warning "Внимание"
    Статус `SUCCESS` не означает, что запрос игрока корректен. Если сервер отклонил запрос или PostgreSQL вернул ошибку, вместо `columns` и `rows` в `result` придёт поле `error`.

Запрос отклонён:

```json
{
  "status": "SUCCESS",
  "result": {
    "error": "Разрешён только SELECT-запрос."
  }
}
```

### Ошибки в поле `result.error`

| Текст ошибки | Причина |
| --- | --- |
| `Пустой или некорректный SQL-запрос.` | Сервер не смог разобрать запрос |
| `Разрешён только SELECT-запрос.` | Запрос изменяет данные или структуру базы |
| `Запрос содержит запрещённые конструкции.` | В запросе есть `;`, комментарий, `INTO` или `RECURSIVE` |
| `Запрос содержит запрещённые SQL-операции.` | В запросе есть, например, `INSERT`, `DROP` или `GRANT` |
| `Доступ к таблице '<таблица>' в этом кейсе запрещён.` | Таблицы нет в материалах дела |
| Текст ошибки PostgreSQL | Ошибка при выполнении запроса, например опечатка в имени поля |
