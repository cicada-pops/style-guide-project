# Тестирование руководства

Чтобы проверить руководство, мы написали по нему два документа для SQL Hunt:

1. [Новый README](readme.md) вместо двух существующих: `README.md` и `backend/README.md`.
2. [Справочник метода API «Выполнение SQL-запроса»](execute-sql.md). Раньше этот метод не был описан.

## Как проверяли

1. Прогнали исходные README через markdownlint и Vale с настройками руководства.
2. Вручную сверили исходные README с каждым правилом и записали нарушения.
3. Написали новые документы по шаблонам и правилам.
4. Прогнали новые документы через линтеры.
5. Записали, каких правил не хватило и какие оказались неудобными.

## Результаты автоматической проверки

| Документ | markdownlint | Vale |
| --- | --- | --- |
| Исходный `README.md` | 8 ошибок | 0 ошибок |
| Исходный `backend/README.md` | 47 ошибок | 0 ошибок |
| Новый README | 0 ошибок | 0 ошибок |
| Справочник метода API | 0 ошибок | 0 ошибок |

В исходных README больше всего ошибок `MD040` и `MD031`: 17 блоков кода без языка и без пустых строк вокруг.

Vale не нашёл ошибок в исходных README, потому что они написаны на английском, а правила Vale рассчитаны на русский текст.
Это ещё один довод за правило [СИ-8](../rules/voice.md#си-8-пишите-документацию-на-русском): правила языка работают, только если документация на одном языке.

## Ошибки в проекте, найденные попутно

Пока сверяли документацию с кодом, нашли расхождения, которые README скрывал:

- README требует Python 3.11, а `pyproject.toml` — Python 3.13 или выше;
- `docker-compose.yml` читает файл `frontend/.env`, но README о нём не упоминает;
- в README команда `make clean_migrations:` написана с двоеточием, и в таком виде она не запустится;
- `make test` вызывает старую команду `docker-compose`, остальные команды — `docker compose`;
- переменных для входа через Google нет в `backend/.env.example`, хотя их читает `settings.py`;
- сообщение API «Доступ к таблице … в этом кейсе запрещён» использует слово «кейс» вместо «дело».

## Каких правил не хватило

По итогам теста мы дополнили руководство:

| Проблема | Что добавили |
| --- | --- |
| Непонятно, какие инструменты нужны для запуска, а какие — только для разработки | В шаблон README — раздельные таблицы «Для запуска» и «Для разработки» со столбцом «Зачем» |
| Ссылка на `https://sqlhunt.com:8000` стояла раньше, чем шаг с настройкой домена | В правило ОТ-3 — требование к порядку шагов |
| В `.env.example` нет части переменных, которые читает код | В правило ТР-3 — описывать все переменные, которые читает код |
| Метод API возвращает результат не сразу, а через отдельный метод | В шаблон метода API — раздел для асинхронных методов |
| Ошибка запроса игрока приходит в теле ответа с кодом `200` | В шаблон метода API — таблицу ошибок в теле ответа |
| Пример SQL в правиле ТР-4 заканчивался точкой с запятой, а SQL Hunt такие запросы отклоняет | В правило ТР-4 — запрет `;` и комментариев в примерах для игроков |

Ещё одну проблему нашли сами линтеры.
<!-- vale SQLHunt.Bureaucratese = NO -->
Первая версия правила Vale `SQLHunt.Bureaucratese` считала канцеляритом слово «данные» в значении «информация».
Мы оставили в правиле только формы «данный», «данная», «данное» и другие, которые означают «этот».
