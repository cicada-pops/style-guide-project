# SQL Hunt

SQL Hunt — веб-игра для тех, кто учит SQL.
Игрок расследует уголовные дела: выполняет SQL-запросы к базе с подозреваемыми, уликами и алиби и называет преступника.

![Игрок открывает дело, выполняет запрос к таблице подозреваемых и отправляет ответ](https://raw.githubusercontent.com/cicada-pops/SQLHunt/main/demo.gif)

## Возможности

- Дела с сюжетом: в каждом нужно найти преступника по материалам дела.
- Редактор SQL-запросов: доступны только запросы `SELECT` к таблицам текущего дела.
- Опыт (XP) за раскрытые дела открывает доступ к новым делам.
- Вход по электронной почте или через Google.

## Требования

Для запуска нужны:

| Инструмент | Версия | Зачем |
| --- | --- | --- |
| Docker | 28 или выше | Запуск всех сервисов в контейнерах |
| Docker Compose | 2 или выше | Описание сервисов в `docker-compose.yml` |
| GNU Make | Любая | Короткие команды из `Makefile` |
| zsh | Любая | Оболочка, в которой `Makefile` выполняет команды |

Для разработки без Docker дополнительно нужны:

| Инструмент | Версия | Зачем |
| --- | --- | --- |
| Python | 3.13 или выше | Бэкенд |
| uv | Любая | Зависимости бэкенда |
| Ruff | Любая | Проверка и форматирование кода Python |
| Node.js | 18 или выше | Фронтенд |
| pnpm | Любая | Зависимости фронтенда |

## Быстрый старт

1. Клонируйте репозиторий и перейдите в его каталог:

    ```bash
    git clone https://github.com/cicada-pops/SQLHunt.git
    cd SQLHunt
    ```

2. Создайте файлы с переменными окружения из примеров:

    ```bash
    cp backend/.env.example backend/.env
    cp frontend/.env.example frontend/.env
    ```

3. Заполните переменные в `backend/.env`. Какие переменные обязательны, написано в разделе [«Переменные окружения»](#переменные-окружения).
4. Добавьте локальный домен в файл `/etc/hosts`:

    ```text
    127.0.0.1       sqlhunt.com
    ```

    Бэкенд работает по адресу `https://sqlhunt.com:8000`, и без этой строки браузер его не найдёт.

5. Запустите все сервисы:

    ```bash
    make up
    ```

    Первый запуск занимает несколько минут: Docker собирает образы, а бэкенд применяет миграции и загружает дела.

6. Откройте `https://sqlhunt.com:8000` и подтвердите переход на сайт. Браузер предупредит о самоподписанном сертификате: его создаёт `runserver_plus` при запуске бэкенда.
7. Откройте `http://localhost:3000`. Появится главная страница SQL Hunt со списком дел.

## Переменные окружения

Переменные бэкенда хранятся в файле `backend/.env`:

| Переменная | Обязательная | Описание | Пример |
| --- | --- | --- | --- |
| `DJANGO_SETTINGS_MODULE` | Да | Модуль настроек Django | `core.config.settings` |
| `DJANGO_SECRET_KEY` | Да | Секретный ключ Django | `<your-secret-key>` |
| `POSTGRES_USER` | Да | Пользователь обеих баз PostgreSQL | `sqlhunt` |
| `POSTGRES_PASSWORD` | Да | Пароль пользователя PostgreSQL | `<your-password>` |
| `CELERY_BROKER_URL` | Да | Адрес брокера RabbitMQ для Celery | `amqp://broker:5672//` |
| `CELERY_REDIS_URL` | Да | Адрес Redis, где Celery хранит результаты запросов | `redis://result:6379` |
| `DEFENDER_REDIS_URL` | Да | Адрес Redis для защиты от подбора пароля | `redis://result:6379/1` |
| `EMAIL_HOST_USER` | Нет | Адрес почты, с которого приходят письма для сброса пароля | `<your-email>` |
| `EMAIL_HOST_PASSWORD` | Нет | Пароль приложения для этой почты | `<your-app-password>` |
| `GOOGLE_OAUTH_CLIENT_ID` | Нет | Идентификатор клиента для входа через Google | `<your-client-id>` |
| `GOOGLE_OAUTH_CLIENT_SECRET` | Нет | Секрет клиента для входа через Google | `<your-client-secret>` |
| `GOOGLE_OAUTH_CALLBACK_URL` | Нет | Адрес возврата после входа через Google | `<your-callback-url>` |

Переменная фронтенда хранится в файле `frontend/.env`:

| Переменная | Обязательная | Описание | Пример |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | Нет | Адрес бэкенда для авторизации. Если не задан, используется `https://sqlhunt.com:8000` | `https://sqlhunt.com:8000` |

## Команды для разработки

Выполняйте команды из корня репозитория.
Имя сервиса для команд `logs` и `shell` берётся из `docker-compose.yml`: `frontend`, `backend`, `celery`, `db1`, `db2`, `broker`, `result`.

| Команда | Что делает |
| --- | --- |
| `make up` | Собирает образы и запускает все сервисы в фоне |
| `make down` | Останавливает все сервисы |
| `make logs <сервис>` | Показывает логи сервиса, например `make logs backend` |
| `make shell <сервис>` | Открывает командную оболочку в контейнере сервиса |
| `make manage <команда>` | Выполняет команду `manage.py` в контейнере бэкенда, например `make manage load_cases` |
| `make createsuperuser` | Создаёт администратора Django |
| `make makemigrations` | Создаёт миграции |
| `make migrate` | Применяет миграции |
| `make test` | Запускает тесты и сохраняет тестовую базу между запусками |
| `make test_reset` | Запускает тесты с новой тестовой базой |
| `make check` | Проверяет код Python с помощью Ruff |
| `make lint` | Исправляет стиль кода Python с помощью Ruff |
| `make clean` | Удаляет кэш Python |
| `make clean_migrations` | Удаляет все файлы миграций, кроме `__init__.py`. Вернуть их можно только из Git |
| `make update_dependencies` | Пересобирает контейнеры после изменения зависимостей |

Чтобы запустить часть тестов, передайте путь к модулю от каталога `backend`:

```bash
make test core.tests.users
```
