# Орфография и пунктуация

Основа — правила русского языка.
Здесь собраны случаи, в которых авторы SQL Hunt ошибаются чаще всего или в которых нужна договорённость.

## ОП-1. Пишите букву «ё»

Пишите «ё» везде, где она произносится: «всё», «ещё», «учётная запись», «отчёт», «счётчик».
Без «ё» некоторые слова читаются двояко: «все» и «всё», «узнаем» и «узнаём».

## ОП-2. Используйте кавычки-«ёлочки»

В тексте используйте «ёлочки».
Для кавычек внутри кавычек используйте „лапки“: «Нажмите „Отправить ответ“».
Прямые кавычки `"` допустимы только в коде.

<!-- vale off -->

| Неправильно | Правильно |
| --- | --- |
| Откройте дело "Серебряный Ключ". | Откройте дело «Серебряный Ключ». |

<!-- vale on -->

Проверка: Vale, правило `SQLHunt.Quotes`.

## ОП-3. Различайте тире и дефис

- Тире «—» с пробелами — между словами: «SQL Hunt — детективная игра».
- Короткое тире «–» без пробелов — в диапазонах: «2004–2010», «5–10 минут».
- Дефис «-» без пробелов — в составных словах: «SQL-запрос», «веб-игра».

<!-- vale off -->

| Неправильно | Правильно |
| --- | --- |
| SQL Hunt - Детективные загадки | SQL Hunt — детективные загадки |
| SQL запрос | SQL-запрос |

<!-- vale on -->

Проверка: Vale, правило `SQLHunt.Dash` находит дефис между пробелами.

## ОП-4. Записывайте числа цифрами

- Числа записывайте цифрами: «3 дела», «100 XP».
- Разряды в числах от 10 000 отделяйте пробелом: «10 000 строк».
- Десятичная дробь в тексте пишется через запятую: «0,5 секунды». В коде и JSON — через точку.
- Единицы измерения пишите после числа через пробел: «1000 строк», «порт 8000».

## ОП-5. Записывайте даты и время единообразно

| Где | Формат | Пример |
| --- | --- | --- |
| Тексты для игроков | День, месяц словом, год | 1 июня 2004 г. |
| Таблицы и списки | ДД.ММ.ГГГГ | 01.06.2004 |
| Справочник API и логи | ISO 8601 | `2004-06-01`, `2004-06-01T02:30:00Z` |

Время записывайте в 24-часовом формате: «02:30», а не «2:30 AM».

## ОП-6. Пишите иноязычные названия в оригинале

Названия продуктов, технологий и компаний пишите латиницей, как у правообладателя: Docker, PostgreSQL, Celery.
Не склоняйте их через апостроф или дефис.
Если нужно склонение, добавьте родовое слово: «в базе PostgreSQL», «в контейнере Docker».

Устоявшиеся заимствования пишите кириллицей: «сервер», «бэкенд», «фронтенд», «коммит», «ветка».
Список написаний — в [словаре](../glossary.md).

<!-- vale off -->

| Неправильно | Правильно |
| --- | --- |
| в Postgres'е | в PostgreSQL |
| запустите докер | запустите Docker |
| back-end | бэкенд |

<!-- vale on -->

Проверка: Vale, правила `SQLHunt.Brands` и `SQLHunt.Words`.

## ОП-7. Не сокращайте слова в тексте

<!-- vale SQLHunt.Abbreviations = NO -->
Не используйте «т. к.», «т. е.», «и т. д.», «напр.» — напишите слова полностью.
<!-- vale SQLHunt.Abbreviations = YES -->

Аббревиатуры расшифровывайте при первом упоминании на странице, если их нет в глоссарии: «опыт (XP)», «JSON Web Token (JWT)».
Общеизвестные аббревиатуры не расшифровывайте: SQL, API, URL, JSON.

Проверка: Vale, правило `SQLHunt.Abbreviations`.

## ОП-8. Оформляйте заголовки как предложения

С прописной буквы пишите только первое слово и имена собственные.
Точку в конце заголовка не ставьте.

<!-- vale off -->

| Неправильно | Правильно |
| --- | --- |
| Запуск Проекта Локально. | Запуск проекта локально |

<!-- vale on -->

Проверка: markdownlint, правило `MD026` (знаки препинания в конце заголовка).

## ОП-9. Не смешивайте латиницу и кириллицу в одном слове

Буквы «а», «е», «о», «с», «р», «х» выглядят одинаково в кириллице и латинице, но это разные символы.
Слово с латинской буквой не находится поиском, а экранный диктор читает его с ошибкой.

<!-- vale SQLHunt.MixedScript = NO -->
В подсказках к полям базы SQL Hunt есть такие ошибки: в «ФИO» последняя буква латинская, в «cтатус» — первая.
<!-- vale SQLHunt.MixedScript = YES -->

Проверка: Vale, правило `SQLHunt.MixedScript`.
