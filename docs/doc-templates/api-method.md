# Шаблон метода API

Справочник API читают фронтенд-разработчики.
Им нужно быстро понять, какой запрос отправить и что придёт в ответ.

Одна страница описывает один метод.
Методы, которые всегда вызываются вместе, можно описать на одной странице.

## Структура

| Раздел | Что написать |
| --- | --- |
| Заголовок | Что делает метод: «Выполнение SQL-запроса» |
| Вступление | Метод, путь и одно предложение о назначении |
| Авторизация | Нужен ли токен и какой |
| Параметры пути | Таблица: параметр, тип, описание |
| Тело запроса | Таблица: поле, тип, обязательное, описание |
| Пример запроса | Команда `curl` |
| Ответ | Пример JSON и таблица полей |
| Коды ответов | Таблица: код, когда возвращается, текст ошибки |
| Ошибки в теле ответа | Таблица ошибок, которые приходят с кодом `200`, если они есть |

## Асинхронные методы

Некоторые методы не возвращают результат сразу, а ставят задачу в очередь.
Например, `POST /api/cases/{case_id}/execute-sql/` возвращает `task_id`, а результат выдаёт `GET /api/sql-task/{task_id}/`.

Такие методы описывайте на одной странице, разделами «Шаг 1» и «Шаг 2»:

- в начале страницы перечислите оба метода и объясните, почему результат приходит не сразу;
- опишите все значения поля статуса и скажите, что делать при каждом из них;
- если ошибка приходит в теле успешного ответа, предупредите об этом блоком «Внимание».

Пример — [справочник метода «Выполнение SQL-запроса»](../examples/execute-sql.md).

````markdown
  -H "Content-Type: application/json" \
  -d '<тело запроса>'
```
````
